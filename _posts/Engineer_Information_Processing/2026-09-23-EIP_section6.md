# 정보처리기사
## 화면 설계
### 86. 사용자 인터페이스
#### [1] 사용자 인터페이스(UI; User Interface)
- **사용자 인터페이스(UI)** : **사용자와 시스템 간의 상호작용이 원할하게 이뤄지도록 도와주는 장치나 소프트웨어**

<br>

#### [2] 사용자 인터페이스의 구분

|구분|내용|
|:---:|:---:|
|CLI(Command Line Interface)|명령과 출력이 텍스트 형태로 이뤄지는 인터페이스|
|GUI(Graphical User Interface)|아이콘이나 메뉴를 마우스로 선택하는 그래픽 환경의 인터페이스|
|NUI(Natural User Interface)|말이나 행동 등 자연스러운 움직임을 통해 기기를 조작하는 인터페이스|

<br>

#### [3] 사용자 인터페이스의 기본 원칙

|원칙|내용|
|:---:|:---:|
|직관성|누구나 쉽게 이해하고 사용|
|유효성|사용자의 목적을 정확하고 완벽하게 달성|
|학습성|누구나 쉽게 배우고 익힐 수 있음|
|유연성|요구사항을 최대한 수용하고 실수를 최소화|

<br>
<br>

### 87. UI 설계 도구
#### [1] 와이어프레임(Wireframe)
- **와이어프레임** : **페이지에 대한 개략적인 레이아웃이나 뼈대를 설계하는 도구**

<br>

#### [2] 목업(Mockup)
- **목업** : **와이어프레임보다 좀 더 실제 화면과 유사하게 만든 정적인 형태의 모형**

<br>

#### [3] 스토리보드(Storyboard)
- **스토리보드** : **와이어프레임에 콘텐츠에 대한 설명, 페이지 간 이동 흐름 등을 추가한 문서**

<br>

#### [4] 프로토타입(Prototype)
- **프로토타입** : **와이어프레임이나 스토리보드 등에 인터랙션을 적용함으로써 실제 구현된 것처럼 테스트가 가능한 동적인 형태의 모형**

- 종류
  - 페이퍼 프로토타입 : 손으로 직접 작성하는 아날로그 형태의 프로토타입
  - 디지털 프로토타입 : 프로그램을 사용하여 작성하는 디지털 형태의 프로토타입

<br>

#### [5] 유스케이스(Use Case)
- **유스케이스** : **사용자의 요구사항을 기능 단위로 표현한 것**

<br>
<br>

### 88. 품질 요구사항
#### [1] 품질 요구사항
- **소프트웨어 품질** : **소프트웨어에 대한 요구사항이 사용자의 입장에서 얼마나 충족하는가를 나타내는 소프트웨어 특성의 총체**

- 소프트웨어 품질 관련 표준
  - ISO/IEC 9126
  - ISO/IEC 25010
  - ISO/IEC 12119
  - ISO/IEC 14598

<br>

#### [2] ISO/IEC 9126의 소프트웨어 품질 특성

|특성|내용|
|:---:|:---:|
|기능성(Functionality)|사용자의 요구사항을 정확하게 만족하는 기능을 제공하는지 여부<br>하위 특성 : 적절성, 정확성, 상호운용성, 보안성, 준수성|
|신뢰성(Reliability)|주어진 기능을 오류 없이 수행할 수 있는 정도<br>하위 특성 : 성숙성, 고장 허용성, 회복성|
|사용성(Usability)|사용자가 정확하게 이해하고 쉽게 사용하며 다시 사용하고 싶은 정도<br>하위 특성 : 이해성, 학습성, 운용성, 친밀성|
|효율성(Efficiency)|요구하는 기능을 얼마나 빠르게 처리할 수 있는지 정도<br>하위 특성 : 시간 효율성, 자원 효율성|
|유지보수성(Maintainability)|새로운 요구사항이 발생했을 때 소프트웨어를 개선하거나 확장할 수 있는 정도<br>하위 특성 : 분석성, 변경성, 안정성, 시험성|
|이식성(Portability)|다른 환경에서도 쉽게 적용할 수 있는지 정도<br>하위 특성 : 적용성, 설치성, 대체성, 공존성|

<br>
<br>

### 89. UI 설계
#### [1] UI 설계서
- UI 설계서 작성 순서
  - (1) UI 설계서 표지 작성
  - (2) UI 설계서 개정 이력 작성
  - (3) UI 요구사항 정의서 작성
  - (4) 시스템 구조 작성
  - (5) 사이트 맵 작성
  - (6) 프로세스 정의서 작성
  - (7) 화면 설계

<br>

- 사이트 맵(Site Map) : 화면의 정보를 한 눈에 파악하기 위한 시각적 컨텐츠 모형으로, 테이블 형태로 구성.

<br>

#### [2] UI 흐름 설계
- UI 흐름 설계 순서
  - (1) 기능 작성
  - (2) 입력 요소 확인
  - (3) 유스케이스 설계
  - (4) 기능 및 양식 확인

<br>

#### [3] UI 상세 설계
- UI 상세 설계 순서
  - (1) 요구사항 확인
  - (2) UI 설계서 표지 및 개정 이력 작성
  - (3) UI 구조 설계
  - (4) 메뉴 구조 설계
  - (5) 화면 설계

<br>

#### [4] UI 시나리오 문서
- UI 시나리오 문서의 요건
  - 완전성(Complete) : 누락되지 않도록 최대한 상세하게
  - 일관성(Consistent) : 모두 일관성을 유지
  - 이해성(Understandable) : 누구나 쉽게 이해
  - 가독성(Readable) : 문서를 쉽게 읽을 수 있도록
  - 수정 용이성(Modifiable) : 수정이나 개선이 쉽도록
  - 추적 가능성(Traceable) : 변경 사항은 쉽게 추적할 수 있도록

<br>
<br>

### 90. HCI / UX / 감성공학
#### [1] HCI(Human Computer Interaction/Interface)
- **HCI** : **사람이 시스템을 편리하고 안전하게 사용할 수 있도록 연구하고 개발하는 학문**

<br>

#### [2] UX(User Experience, 사용자 경험)
- **UX** : **사용자가 시스템이나 서비스를 이용하면서 느끼고 생각하게 되는 총체적인 경험**

- UX의 특징
  - 주관성(Subjectivity) : UX는 사용자의 주관적인 경험
  - 정황성(Contextuality) : 경험이 일어나는 상황 또는 주변 환경에 영향을 받음
  - 총체성(Holistic) : 개인이 느끼는 총체적인 심리적, 감성적 결과

<br>

#### [3] 감성공학
- **감성공학** : **제품이나 작업환경을 사용자의 감성에 알맞도록 설계 및 제작하는 기술**
