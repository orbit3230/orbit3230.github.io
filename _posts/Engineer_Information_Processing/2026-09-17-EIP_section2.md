# 정보처리기사
## 데이터 입·출력 구현
### 29. 데이터베이스 개요
#### [1] 데이터베이스(Database)
- **데이터베이스** : **공동으로 사용될 데이터를 중복을 배제하여 통합하고, 저장장치에 저장하여 항상 사용할 수 있도록 운영하는 운영 데이터**

- 데이터베이스는 다음과 같이 구분하여 정의할 수 있다.
  - 통합된 데이터(Integrated Data) : 자료의 중복을 배제
  - 저장된 데이터(Stored Data) : 저장 매체에 저장
  - 운영 데이터(Operational Data) : 조직의 고유한 업무를 수행하는데 필요한 자료
  - 공유된 데이터(Shared Data) : 여러 운영 시스템들이 공동으로 소유

<br>

#### [2] DBMS(DataBase Management System; 데이터베이스 관리 시스템)
- **DBMS** : **사용자의 요구에 따라 정보를 생성해주고 데이터베이스를 관리해주는 소프트웨어**

- DBMS의 필수 기능 3가지
  - **정의(Definition) 기능** : 데이터 타입과 구조에 대한 정의, 이용 방식과 제약 조건 명시
  - **조작(Manipulation) 기능** : 데이터 검색, 갱신, 삽입, 삭제 등을 위해 인터페이스 제공
  - **제어(Control) 기능** : 데이터의 무결성, 보안, 권한 검사, 병행 제어를 제공

<br>

#### [3] 데이터의 독립성
- **논리적 독립성** : 응용 프로그램과 데이터베이스를 독립
- **물리적 독립성** : 응용 프로그램과 물리적 저장 장치를 독립

<br>

#### [4] 스키마(Schema)
- **스키마** : **데이터베이스의 구조와 제약조건에 관한 전반적인 명세를 기술한 것**

|종류|내용|
|:---:|:---:|
|외부 스키마|사용자 관점에서 필요로 하는 데이터베이스의 논리적 구조|
|개념 스키마|데이터베이스의 전체적인 논리적 구조|
|내부 스키마|물리적 저장장치 관점에서의 데이터베이스 구조|

<br>
<br>

### 30. 데이터베이스 설계
#### [1] 데이터베이스 설계 시 고려사항

|항목|내용|
|:---:|:---:|
|무결성|삽입, 삭제, 갱신 등의 연산 후에도 정해진 제약 조건을 항상 만족|
|일관성|특정 질의에 대한 응답이 처음부터 끝까지 변함없이 일정|
|회복|시스템에 장애가 발생했을 때 발생 직전의 상태로 복구 가능|
|보안|데이터의 노출 또는 변경이나 손실로부터 보호|
|효율성|응답시간의 단축, 시스템의 생산성, 저장 공간의 최적화 등이 가능|
|데이터베이스 확장|운영에 영향을 주지 않으면서 지속적으로 데이터 추가 가능|

<br>

#### [2] 데이터베이스 설계 순서
- 요구 조건 분석 → 개념적 설계 → 논리적 설계 → 물리적 설계 → 구현

<br>

#### [3] 요구 조건 분석
- **요구 조건 분석** : **데이터베이스의 필요한 용도를 파악하는 것**

<br>

#### [4] 개념적 설계(정보 모델링, 개념화)
- **개념적 설계** : **현실 세계에 대한 인식을 추상적 개념으로 표현하는 과정**

- **개념 스키마** / **트랜잭션 모델링** / **E-R 모델링**

<br>

#### [5] 논리적 설계(데이터 모델링)
- **논리적 설계** : **현실 세계에서 발생하는 자료를 특정 DBMS가 지원하는 논리적 자료 구조로 변환(mapping)하는 과정**

- **논리 스키마 설계** / **트랜잭션 인터페이스 설계**

<br>

#### [6] 물리적 설계(데이터 구조화)
- **물리적 설계** : **논리적 구조로 표현된 데이터를 물리적 구조의 데이터로 변환하는 과정**

<br>

#### [7] 데이터베이스 구현
- **데이터베이스 구현** : **논리적 설계와 물리적 설계에서 도출된 데이터베이스 스키마를 파일로 생성하는 과정**

- **DDL로 작성** / **트랜잭션 작성**  

<br>
<br>

### 31. 데이터 모델의 개념
#### [1] 데이터 모델
- **데이터 모델** : **현실 세계의 정보들을 단순화, 추상화하여 체계적으로 표현한 개념적 모형**

- 데이터 모델 구성 요소 : 개체, 속성, 관계
- 데이터 모델 종류 : 개념적 데이터 모델, 논리적 데이터 모델, 물리적 데이터 모델
- 데이터 모델에 표시할 요소 : 구조, 연산, 제약 조건

<br>

#### [2] 개념적 데이터 모델
- **개념적 데이터 모델** : **현실 세계에 대한 인간의 이해를 돕기 위해 현실 세계에 대한 인식을 추상적 개념으로 표현하는 과정**

<br>

#### [3] 논리적 데이터 모델
- **논리적 데이터 모델** : **개념적 구조를 컴퓨터 세계의 환경에 맞도록 변환하는 과정**

<br>

#### [4] 데이터 모델에 표시한 요소

|요소|내용|
|:---:|:---:|
|구조(Structure)|논리적으로 표현된 개체 타입들 간의 관계|
|연산(Operation)|실제 데이터를 처리하는 작업에 대한 명세|
|제약 조건(Constraint)|실제 데이터의 논리적인 제약 조건에 대한 명세|

<br>
<br>

### 32. 데이터 모델의 구성 요소
#### [1] 개체(Entity)
- **개체** : **데이터베이스에 표현하려는 것**으로, 사람이 생각하는 **개념이나 단위 같은 현실 세계의 대상체**

<br>

#### [2] 속성(Attribute)
- **속성** : **데이터베이스를 구성하는 가장 작은 논리적 단위**

<br>

#### [3] 속성의 특성에 따른 분류

|분류|내용|
|:---:|:---:|
|기본 속성(Basic Attribute)|업무 분석을 통해 정의한 속성|
|설계 속성(Designed Attribute)|설계 과정에서 도출해내는 속성|
|파생 속성(Derived Attribute)|다른 속성으로부터 계산이나 변형 등의 영향을 받아 발생하는 속성|

<br>

#### [4] 속성의 개체 구성 방식에 따른 분류

|분류|내용|
|:---:|:---:|
|기본키 속성(Primary Key Attribute)|개체를 유일하게 식별할 수 있는 속성|
|외래키 속성(Foreign Key Attribute)|다른 개체와의 관계에서 포함된 속성|
|일반 속성|개체에 포함되어 있지만 기본키나 외래키에 포함되지 않은 속성|

<br>

#### [5] 관계(Relationship)
- **관계** : **개체와 개체 사이의 논리적인 연결**

<br>

#### [6] 관계의 형태
- 일 대 일(1:1)
- 일 대 다(1:N)
- 다 대 다(N:M)

<br>

#### [7] 관계의 종류
- 종속 관계(Dependent Relationship) : 두 개체 사이의 주·종 관계
- 중복 관계(Duplicate Relationship) : 두 개체 사이에 2번 이상의 종속 관계가 발생
- 재귀 관계(Recursive Relationship) : 개체가 자기 자신과 관계를 갖는 것
- 배타 관계(Exclusive Relationship) : 개체의 속성이나 구분자를 기준으로 개체의 특정을 분할하는 관계

<br>
<br>

### 33. E-R(개체-관계) 모델
#### [1] E-R(Entity-Relationship, 개체-관계) 모델
- **E-R 모델** : **개체와 개체 간의 관계를 기본 요소로 이용하여 현실 세계의 데이터를 개념적인 논리 데이터로 표현하기 위한 방법

- 가장 대표적인 개념적 데이터 모델
- 데이터를 개체(Entity), 속성(Attribute), 관계(Relationship)로 표현

<br>

#### [2] E-R 다이어그램

|기호 이름|의미|
|:---:|:---:|
|사각형|개체(Entity) 타입|
|마름모|관계(Relationship) 타입|
|타원|속성(Attribute)|
|이중 타원|다중값 속성(복합 속성)|
|밑줄 타원|기본키 속성|
|복수 타원|복합 속성|
|관계|1:1, 1:N, N:M 관계|
|선, 링크|개체 타입과 속성을 연결|

<br>
<br>

### 34. 관계형 데이터베이스의 구조 / 관계형 데이터 모델
#### [1] 관계형 데이터베이스
- **관계형 데이터베이스** : **2차원적인 표(Table)를 이용해서 데이터 상호 관계를 정의하는 데이터베이스**

<br>

#### [2] 튜플(Tuple)
- **튜플** : **릴레이션을 구성하는 각각의 행**

- 카디널리티(Cardinality, 기수, 대응수) : 릴레이션에 포함된 튜플의 수

<br>

#### [3] 속성(Attribute)
- **속성** : **데이터베이스를 구성하는 가장 작은 논리적 단위**

- 디그리(Degree, 차수) : 릴레이션에 포함된 속성의 수

<br>

#### [4] 도메인(Domain)
- **도메인** : **하나의 속성이 취할 수 있는 같은 타입의 원자(Atomic)값의 집합

<br>

#### [5] 릴레이션의 특징
- 릴레이션에 포함된 튜플은 모두 상이하다.
- 튜플 사이에는 순서가 없다.
- 연산 작업으로 인해 릴레이션은 시간에 따라 변한다.
- 속성들 간의 순서는 중요하지 않다.
- 속성의 명칭은 유일해야 한다.
- 속성들의 부분집합을 키(Key)로 설정한다.
- 속성의 값은 논리적으로 더 이상 쪼갤 수 없는 원자값이어야 한다.  

<br>

#### [5] 관계형 데이터 모델
- **관계형 데이터 모델** : **2차원적인 표(Table)를 이용해서 데이터 상호 관계를 정의하는 DB 구조**  

<br>
<br>

### 35. 관계형 데이터베이스의 제약 조건 - 키(Key)
#### [1] 후보키(Candidate Key)
- **후보키** : **속성들 중에서 튜플을 유일하게 식별하기 위해 사용되는 속성들의 부분집합**

- 후보키는 아래 두 가지 조건을 만족해야 한다.
  
|조건|설명|
|:---:|:---:|
|유일성(Unique)|하나의 키 값으로 하나의 튜플만을 유일하게 식별|
|최소성(Minimality)|키를 구성하는 속성 하나를 제거하면 유일하게 식별할 수 없도록 꼭 필요한 최소의 속성|

<br>

#### [2] 기본키(Primary Key)
- **기본키** : **후보키 중에서 특별히 선정된 주 키(Main Key)**

<br>

#### [3] 대체키(Alternate Key)
- **대체키** : **후보키가 둘 이상일 때 기본키를 제외한 나머지 후보키**

<br>

#### [4] 슈퍼키(Super Key)
- **슈퍼키** : **속성들의 집합으로 구성된 키**

- 유일성은 만족하지만 최소성은 만족하지 못하는 키

<br>

#### [5] 외래키(Foreign Key)
- **외래키** : **다른 릴레이션의 기본키를 참조하는 속성 또는 속성들의 집합**

<br>
<br>

### 36. 관계형 데이터베이스의 제약 조건 - 무결성(Integrity)
#### [1] 무결성(Integrity)
- **무결성** : **데이터베이스에 저장된 데이터 값과 현실 세계의 실제 값이 일치하는 정확성**

<br>

#### [2] 무결성의 종류

|종류|내용|
|:---:|:---:|
|개체 무결성|기본키를 구성하는 어떤 속성도 Null 값이나 중복값을 가질 수 없다|
|참조 무결성|외래키는 Null이거나, 참조 릴레이션의 기본키 값과 동일해야 한다|
|도메인 무결성|주어진 속성 값이 정의된 도메인에 속한 값이어야 한다|
|사용자 정의 무결성|속성 값들이 사용자가 정의한 제약조건에 만족되어야 한다|

<br>
<br>

### 37. 관계대수 및 관계해석
#### [1] 관계대수
- **관계대수** : **원하는 정보와 그 정보를 검색하기 위해서 어떻게 유도하는가를 기술하는 절차적인 언어**

<br>

#### [2] 순수 관계 연산자

|종류|특징|기호|
|:---:|:---:|:---:|
|Select|선택 조건을 만족하는 튜플을 구하는 수평 연산|`σ`|
|Project|제시된 속성 값만을 추출하는 수직 연산|`π`|
|Join|공통 속성을 중심으로 두 릴레이션을 하나로 합치는 연산|`⋈`|
|Division|두 릴레이션 `R`과 `S`가 있을 때, `R`의 속성이 `S`의 속성을 모두 가진 튜플에서 `S`가 가진 속성을 제외한 나머지 속성만을 추출하는 연산|`÷`|

<br>

#### [3] 일반 집합 연산자
- **일반 집합 연산자** : **수학적 집합 이론에서 사용하는 연산자**

|연산자|기능 및 수학적 표현|
|:---:|:---:|
|합집합(UNION, `∪`)|튜플의 합집합을 구하되 중복은 제거|
|교집합(INTERSECTION, `∩`)|튜플의 교집합을 구하는 연산|
|차집합( DIFFERENCE, `−`)|튜플의 차집합을 구하는 연산|
|교차곱(CARTESIAN PRODUCT, `×`)|튜플의 순서쌍을 구하는 연산|

- 카르테시안 곱 연산의 Degree는 두 릴레이션의 Degree를 합한 값이 된다.
- 카르테시안 곱 연산의 Cardinality는 두 릴레이션의 Cardinality를 곱한 값이 된다.

<br>
<br>

### 38. 이상 / 함수적 종속
#### [1] 이상(Anomaly)
- **이상** : **테이블에서 데이터의 중복이 발생하고, 이 중복(Redundancy)으로 인해 문제가 발생하는 현상**

- 이상의 종류
  - 삽입 이상(Insertion Anomaly) : 데이터를 삽입할 때 원하지 않은 값들로 인해 삽입할 수 없는 현상
  - 삭제 이상(Deletion Anomaly) : 의도와는 상관없는 값들도 합께 삭제되는, 즉 연쇄 삭제가 발생하는 현상
  - 갱신 이상(Update Anomaly) : 튜플에 있는 속성 값을 갱신할 때 일부 튜플의 정보만 갱신되어 정보에 불일치성(Inconsistency)이 발생하는 현상

<br>

#### [2] 함수적 종속(Functional Dependency)
- **함수적 종속** : **속성 X의 값 각각에 대해 항상 속성 Y의 값이 오직 하나만 연관되어 있을 때 Y는 X에 함수적 종속 또는 X가 Y를 결정한다고 표현**, **`X → Y`로 표기**  

<br>

- **완전 함수적 종속**(Full Functional Dependency) : **속성 Y가 속성 X에만 의존하고, X의 부분집합에는 의존하지 않는 경우**

- **부분 함수적 종속**(Partial Functional Dependency) : **속성 Y가 속성 X에 의존하지만, X의 부분집합에도 의존하는 경우**

- **이행적 함수적 종속**(Transitive Functional Dependency) : **`X → Y`이고 `Y → Z`이면 `X → Z`가 성립하는 경우**

<br>
<br>

### 39. 정규화(Normalization)
#### [1] 정규화(Normalization)
- **정규화** : **테이블의 속성들이 상호 종속적인 관계를 갖는 특성을 이용하여 테이블을 무손실 분해하는 과정**

<br>

#### [2] 정규화 과정
- **제1정규형(1NF)** : **모든 속성의 도메인이 원자 값(Atomic Value)으로만 구성되어 있는 상태**

<br>

- **제2정규형(2NF)** : **제1정규형을 만족하고, 기본키가 아닌 모든 속성이 기본키에 완전 함수적 종속을 만족하는 상태**

<br>

- **제3정규형(3NF)** : **제2정규형을 만족하고, 기본키가 아닌 모든 속성이 기본키에 대해 이행적 함수적 종속을 만족하지 않는 상태**
  - 즉, 기본키가 아닌 속성이 다른 기본키가 아닌 속성을 결정하는 경우가 없도록 하는 상태

<br>

- **BCNF(Boyce-Codd Normal Form)** : **모든 결정자가 후보키인 상태**
  - 즉, 후보키가 아닌 속성이 후보키를 결정하는 경우가 없도록 하는 상태

<br>

- **제4정규형(4NF)** : **다치 종속(Multi-valued Dependency)을 제거한 상태**
  
<br>

- **제5정규형(5NF)** : **모든 조인 종속(Join Dependency)이 후보키에 의해 결정되는 상태**
  - 즉, 후보키가 아닌 속성이 후보키를 결정하는 경우가 없도록 하는 상태  

<br>
<br>

### 40. 반정규화(Denormalization)
#### [1] 반정규화(= 비정규화)
- **반정규화** : **정규화된 데이터 모델을 의도적으로 통합, 중복, 분리하여 정규화 원칙을 위배하는 행위**

<br>

#### [2] 테이블 통합
- **테이블 통합** : **두 테이블이 조인되어 사용되는 경우가 많을 때, 하나의 테이블로 통합하여 사용하는 것**

<br>

#### [3] 테이블 분할
- **테이블 분할** : **테이블을 수직 또는 수평으로 분할하는 것**

|방법|내용|
|:---:|:---:|
|수평 분할|레코드(record)를 기준으로 테이블을 분할<br>이유 : 레코드별로 사용 빈도의 차이가 큰 경우|
|수직 분할|속성(attribute)을 기준으로 테이블을 분할<br>이유 : 속성별로 사용 빈도의 차이가 크거나 보안상 분리가 필요한 경우|

<br>

#### [4] 중복 테이블 추가
- **중복 테이블 추가** : **조회 성능 향상을 위해 일부 속성만을 가진 테이블을 추가하는 것**

- 중복 테이블 추가 방법
  - 집계 테이블의 추가 : 집계 데이터를 위한 테이블을 생성하고, 원본 테이블에 트리거를 설정하여 사용
  - 진행 테이블의 추가 : 이력 관리 등의 목적으로 추가
  - 특정 부분만을 포함하는 테이블의 추가 : 데이터가 많은 테이블의 특정 부분만을 포함하는 테이블을 추가

<br>

#### [5] 중복 속성 추가
- **중복 속성 추가** : **데이터를 조회하는 경로를 단축하기 위해 자주 사용하는 속성을 하나 더 추가하는 것**

<br>
<br>

### 41. 시스템 카탈로그
#### [1] 시스템 카탈로그(System Catalog)
- **시스템 카탈로그** : **다양한 객체에 관한 정보를 포함하는 시스템 데이터베이스**

- 데이터 사전이라고도 한다.

<br>

#### [2] 메타 데이터(Meta Data)
- **메타 데이터** : **시스템 카탈로그에 저장된 정보**

- 메타 데이터의 유형
  - 데이터베이스 객체 정보 : 테이블, 인덱스, 뷰 등의 구조 및 통계 정보
  - 사용자 정보 : 아이디, 패스워드, 접근 권한 등
  - 테이블의 무결성 제약 조건 정보 : 기본키, 외래키, NULL 값 허용 여부 등
  - 함수, 프로시저, 트리거 등에 대한 정보

<br>

#### [3] 데이터 디렉터리(Data Directory)
- **데이터 디렉터리(Data Directory)** : **데이터 사전(시스템 카탈로그)에 수록된 데이터에 접근하는 데 필요한 정보를 고나리 유지하는 시스템**

- 데이터 디렉터리는 시스템만 접근할 수 있다.

<br>
<br>

### 42. 트랜잭션 분석 / CRUD 분석
#### [1] 트랜잭션(Transaction)
- **트랜잭션** : **하나의 논리적 기능을 수행하기 위한 작업의 단위** 또는 **한꺼번에 수행되어야 할 일련의 연산들**

<br>

#### [2] 트랜잭션의 특성

|특성|의미|
|:---:|:---:|
|Atomicity(원자성)|트랜잭션의 연산은 데이터베이스에 모두 반영되거나(**Commit**), 전혀 반영되지 않도록 복구되어야 한다(**Rollback**)|
|Consistency(일관성)|트랜잭션이 성공적으로 완료되면 언제나 일관성 있는 데이터베이스 상태로 변환되어야 한다|
|Isolation(독립성)|트랜잭션이 병행 수행될 때, 다른 트랜잭션의 연산이 실행 중에 끼어들 수 없다.|
|Durability(지속성)|성공적으로 완료된 트랜잭션의 결과는 영구적으로 반영되어야 한다.|

<br>

#### [3] CRUD 분석
- **CRUD 분석** : **프로세스와 테이블 간에 CRUD 매트릭스를 만들어서 트랜잭션을 분석하는 것**  

<br>
<br>

### 43. 인덱스
#### [1] 인덱스(Index)
- **인덱스** : **데이터 레코드를 빠르게 접근하기 위해 `<키 값, 포인터>` 싸으로 구성되는 데이터 구조**

<br>

#### [2] 인덱스의 종류

|종류|내용|
|:---:|:---:|
|트리 기반 인덱스|인덱스를 저장하는 블록들이 트리 구조|
|비트맵 인덱스|인덱스 컬럼의 데이터를 0 또는 1로 변환하여 인덱스 키로 사용|
|함수 기반 인덱스|컬럼의 값 대신 컬럼에 특정 함수나 수식을 적용|
|비트맵 조인 인덱스|다수의 조인된 객체로 구성된 인덱스|
|도메인 인덱스|필요한 인덱스를 직접 만들어 사용|

<br>

#### [3] 클러스티드/넌클러스티드 인덱스

|종류|내용|
|:---:|:---:|
|클러스티드 인덱스(Clustered Index)|인덱스 키의 순서에 따라 데이터도 정렬되어 저장되는 인덱스<br>검색 속도가 빠름|
|넌클러스티드 인덱스(Non-Clustered Index)|인덱스 키 값만 정렬되어 있고, 실제 데이터는 정렬되지 않는 방식<br>삽입, 삭제가 빠름|

<br>
<br>

### 44. 뷰 / 클러스터
#### [1] 뷰(View)
- **뷰** : **하나 이상의 테이블에서 유도된 가상 테이블**

- 뷰의 특징
  - 뷰는 저장장치 내에 물리적으로 존재하지 않음
  - 뷰가 정의된 기본 테이블이나 뷰를 삭제하면 연쇄 삭제가 발생
  - 뷰를 정의할 때는 `CREATE`, 제거할 때는 `DROP`

<br>

#### [2] 뷰의 장·단점

|장점|단점|
|:---:|:---:|
|논리적 데이터 독립성을 제공<br>동시에 여러 사용자의 요구를 충족<br>데이터 관리가 간단<br>자동 보안이 가능|독립적인 인덱스를 가질 수 없음<br>뷰의 정의를 변경할 수 없음<br>삽입, 삭제, 갱신 연산에 제약|

<br>

#### [3] 클러스터(Cluster)
- **클러스터** : **동일한 성격의 데이터를 동일한 데이터 블록에 저장하는 물리적 저장 방법**

- 처리 범위가 넓은 경우 → 단일 테이블 클러스터링
- 조인이 많이 발생하는 경우 → 다중 테이블 클러스터링

<br>
<br>

### 45. 파티션
#### [1] 파티션(Partition)
- **파티션** : **대용량의 테이블이나 인덱스를 작은 논리적 단위인 파티션으로 나누는 것**

<br>

#### [2] 파티션의 장·단점

|장점|단점|
|:---:|:---:|
|쿼리 성능의 향상<br>디스크 성능의 향상<br>백업 및 복구 속도의 향상<br>시스템 장애 시 데이터 손상 최소화<br>데이터 가용성 향상<br>입·출력 분산 가능|세심한 관리가 요구됨<br>조인에 대한 비용의 증가<br>용량이 작은 테이블에 대해서는 역효과 발생|

<br>

#### [3] 파티션의 종류

|종류|내용|
|:---:|:---:|
|범위 분할(Range Partitioning)|지정한 열의 값을 기준으로 분할|
|해시 분할(Hash Partitioning)|해시 값에 따라 데이터를 분할<br>데이터를 고르게 분산할 수 있음|
|조합 분할(Composite Partitioning)|범위 분할로 분할한 다음 해시 함수를 적용|

<br>
<br>

### 46. 분산 데이터베이스 설계
#### [1] 분산 데이터베이스 설계
- **분산 데이터베이스 설계** : **논리적으로는 하나의 시스템에 속하지만 물리적으로는 네트워크를 통해 연결된 여러 개의 사이트(Site)에 분산된 데이터베이스**

<br>

#### [2] 분산 데이터베이스의 목표
- **위치 투명성(Location Transparency)** : 데이터베이스의 실제 위치를 알 필요 없이 논리적인 명칭 만으로 액세스

- **중복 투명성(Replication Transparency)** : 동일 데이터가 여러 곳에 중복되어 있더라도 마치 하나의 데이터만 존재하는 것처럼 액세스

- **병행 투명성(Concurrency Transparency)** : 다수의 트랜잭션이 동시에 수행되더라도 결과는 영향을 받지 않도록 보장

- **장애 투명성(Failure Transparency)** : 시스템에 장애가 발생하더라도 트랜잭션을 정확하게 처리

<br>

#### [3] 분산 설계 방법

|방법|설명|
|:---:|:---:|
|테이블 위치 분산|테이블을 각기 다른 서버에 분산시켜 배치|
|분할(Fragmentation)|테이블의 데이터를 분할하여 분산<br>수평 분할과 수직 분할이 있다.|
|할당(Allocation)|동일한 분할을 여러 개의 서버에 생성|

<br>
<br>

### 47. 데이터베이스 이중화 / 서버 클러스터링\
#### [1] 데이터베이스 이중화(Database Redundancy)
- **데이터베이스 이중화** : **동일한 데이터베이스를 복제하여 관리하는 것**

<br>

#### [2] 데이터베이스 이중화의 분류

|분류|내용|
|:---:|:---:|
|Eager 기법|트랜잭션 수행 중 데이터 변경이 발생하면 모든 데이터베이스에 즉시 전달하여 즉시 적용|
|Lazy 기법|트랜잭션 수행이 종료되면 변경 사실을 새로운 트랜잭션으로 기록하고, 일정 시간 후에 다른 데이터베이스에 적용|

<br>

#### [3] 데이터베이스 이중화 구성 방법

|방법|내용|
|:---:|:---:|
|활동-대기(Active-Standby) 방법|한 DB가 활성 상태로 서비스하고 있으면, 다른 DB는 대기 상태로 있다가 장애 발생 시 활성 상태로 전환|
|활동-활동(Active-Active) 방법|두 DB가 서로 다른 서비스를 제공하다가 한 쪽에 장애가 발생하면 다른 DB가 서비스를 제공|

<br>

#### [4] 클러스터링(Clustering)
- **클러스터링** : **두 대 이상의 서버를 하나의 서버처럼 운영하는 기술**

- 클러스터링 종류

|종류|내용|
|:---:|:---:|
|고가용성 클러스터링|하나의 서버에 장애가 발생하면 다른 노드(서버)가 받아 처리|
|병렬 처리 클러스터링|하나의 작업을 여러 개의 서버에서 분산하여 처리|

<br>

#### [5] RTO와 RPO

|용어|설명|
|:---:|:---:|
|RTO(Recovery Time Objective, 목표 복구 시간)|중단 시점으로부터 복구되어 가동될 떄까지의 소요 시간|
|RPO(Recovery Point Objective, 목표 복구 시점)|데이터를 복구할 수 있는 기준점(시점)|

<br>
<br>

### 48. 데이터베이스 보안
#### [1] 암호화(Encryption)
- **암호화(Encryption) 과정** : 암호화되지 않은 평문을 암호문으로 바꾸는 과정
- **복호화(Decryption) 과정** : 암호문을 원래의 평문으로 바꾸는 과정

- 암호화 기법
  - 개인키 암호 방식(Private Key Encryption) - 대칭키 암호 방식
  - 공개키 암호 방식(Public Key Encryption) - 비대칭키 암호 방식

<br>

#### [2] 접근통제
- 접근통제 3요소
  - 접근통제 정책
  - 접근통제 메커니즘
  - 접근통제 보안모델

<br>

- 접근통제 기술

|정책|특징|
|:---:|:---:|
|임의 접근통제(DAC, Discretionary Access Control)|사용자의 신원에 따라 접근 권한을 부여하는 방식|
|강제 접근통제(MAC, Mandatory Access Control)|주체와 객체의 등급을 비교하여 접근 권한을 부여하는 방식|
|역할 기반 접근통제(RBAC, Role Based Access Control)|사용자의 역할에 따라 접근 권한을 부여하는 방식|

<br>

#### [3] 접근통제 정책
- 접근통제 정책의 종류

|종류|특징|
|:---:|:---:|
|신분 기반 정책|IBP(Individual-Based Policy) : 최소 권한 정책으로, 단일 주체에게 하나의 객체에 대한 허가를 부여<br>GBP(Group-Based Policy) : 복수 주체에게 하나의 객체에 대한 허가를 부여|
|규칙 기반 정책|MLP(Multi-Level Policy) : 사용자나 객체별로 지정된 기밀 분류에 따른 정책<br>CBP(Compartment-Based Policy) : 집단별로 지정된 기밀 허가에 따른 정책|
|역할 기반 정책|주체의 신분이 아니라 주체가 맡은 역할에 근거하여 객체의 접근을 제한|

<br>

#### [4] 접근통제 메커니즘
- **접근통제 메커니즘** : **정의된 접근통제 정책을 구현하는 기술적인 방법**

<br>

#### [5] 접근통제 보안모델
- **접근통제 보안모델** : **보안 정책을 구현하기 위한 정형화된 모델**

- 접근통제 보안모델의 종류

|종류|특징|
|:---:|:---:|
|기밀성 모델|군사적인 목적으로 개발된 최초의 수학적 모델|
|무결성 모델|무결성을 기반으로 개발된 모델|
|접근통제 모델|접근통제 메커니즘을 보안 모델로 발전시킨 것<br>대표적으로 접근통제 행렬(Access Control Matrix)이 있음|

<br>

#### [6] 접근통제 조건
- **값 종속 통제(Value-Dependent Control)** : 객체에 저장된 값에 따라 다르게 접근통제를 허용해야 하는 경우에 사용

- **다중 사용자 통제(Multi-User Control)** : 지정된 객체에 다수의 사용자가 동시에 접근을 요구하는 경우에 사용

- **컨텍스트 기반 통제(Context-Based Control)** : 특정 시간, 네트워크 주소, 접근 경로, 인증 수준 등에 근거하여 접근을 제어

<br>

#### [7] 감사 추적
- **감사 추적(Audit Trail)** : **사용자나 애플리케이션이 데이터베이스에 접근하여 수행한 모든 화동을 기록하는 기능**

<br>

### 49. 데이터베이스 백업

- **로그 파일** : **데이터베이스의 상태 변화를 시간의 흐름에 따라 모두 기록한 파일**

#### [2] 데이터베이스 복구 알고리즘

|종류|내용|
|:---:|:---:|
|NO-UNDO/REDO|버퍼의 내용을 비동기적으로 갱신한 경우의 복구 알고리즘<br>트랜잭션 완료 전에는 기록되지 않으므로 NO-UNDO, 버퍼에 기록되어 있지만 저장매체에 기록되지 않았으므로 REDO|
|UNDO/NO-REDO|버퍼의 내용을 동기적으로 갱신한 경우의 복구 알고리즘<br>변경된 내용을 취소해야 하므로 UNDO, 버퍼 내용을 이미 기록햇으므로 NO-REDO|
|UNDO/REDO|버퍼의 내용을 동기/비동기적으로 갱신한 경우의 복구 알고리즘<br>기록 전에 트랜잭션이 완료되었을 수 있으므로 다시 실행(UNDO & REDO)|
|NO-UNDO/NO-REDO|동기적으로 저장 매체에 기록하지만 데이터베이스가 아닌 다른 영역에 기록한 경우의 복구 알고리즘<br>다른 영역에 기록되므로 NO-UNDO & NO-REDO|

<br>

#### [3] 백업 종류
- 물리 백업

  - 백업/복원 속도가 빠르지만 원인 파악이 어렵다.

- 논리 백업
  - DB 내의 논리적 객체들을 백업
  - 백업/복원 속도가 느리지만 원인 파악이 쉽다.

### 52. 자료 구조
#### [1] 배열(Array)
- **배열** : **크기와 형(Type)이 동일한 자료들이 순서대로 나열된 자료의 집합**

<br>

#### [2] 연속 리스트(Contiguous List)
- **연속 리스트** : 배열과 같이 **연속되는 기억장소에 저장되는 자료 구조**

<br>

#### [3] 연결 리스트(Linked List)
- **연결 리스트** : **자료들을 임의의 기억공간에 기억시키되, 노드의 포인터 부분을 이용하여 서로 연결시킨 자료 구조**

<br>

#### [4] 스택(Stack)
- **스택** : **리스트의 한쪽 끝으로만 자료의 삽입, 삭제 작업이 이루어지는 자료구조**(LIFO, Last In First Out)

<br>

#### [5] 큐(Queue)
- **큐** : **리스트의 한쪽에서는 삽입 작업이 이루어지고 다른 한쪽에서는 삭제 작업이 이루어지는 자료구조**(FIFO, First In First Out)

<br>

#### [6] 그래프(Graph)
- **그래프** : **정점(Vertex)과 간선(Edge)의 두 집합으로 이루어지는 자료 구조**

<br>

#### [7] 방향/무방향 그래프의 최대 간선 수
- 방향 그래프의 최대 간선 수 : `n(n-1)` = <sub>`4`</sub>`P`<sub>`2`</sub>
- 무방향 그래프의 최대 간선 수 : `n(n-1)/2` = <sub>`4`</sub>`C`<sub>`2`</sub>

<br>

### 53. 트리(Tree)
#### [1] 트리
- **트리** : **정점(Node, 노드)과 선분(Branch, 가지)을 이용하여 사이클을 가지지 않도록 구성한 그래프의 특수한 형태**

<br>

#### [2] 트리 관련 용어
- 노드(Node) : 트리의 기본 요소로서, 자료 항목과 다른 항목에 대한 가지(Branch)를 합친 것

- 근 노드(Root Node) : 트리의 맨 위에 있는 노드

- 디그리(Degree, 차수) : 각 노드에서 뻗어나온 가지의 수

- 단말 노드(Terminal Node) = 잎 노드(Leaf Node) : 자식이 하나도 없는, 즉 Degree가 `0`인 노드

- 비단말 노드(Non-Terminal Node) = 내부 노드(Internal Node) : 자식이 하나라도 있는, 즉 Degree가 `1` 이상인 노드

- 조상 노드(Ancestor Node) : 특정 노드에서 루트 노드까지의 경로에 있는 모든 노드

- 자식 노드(Son Node) : 특정 노드에 연결된 다음 레벨의 노드들

- 부모 노드(Parent Node) : 특정 노드에 연결된 이전 레벨의 노드

- 형제 노드(Brother Node, Sibling Node) : 동일한 부모를 갖는 노드들

- Level : 루트 노드의 Level을 `1`로 가정한 후 특정 노드의 Level이 `N`이면 자식 노드는 `N+1`

- 깊이(Depth, Height) : 트리에서 노드가 가질 수 있는 최대의 Level

- 숲(Forest) : 트리의 집합

- 트리의 Degree : 노드들의 Degree 중에서 가장 큰 값

<br>
<br>

### 54. 이진 트리(Tree)
#### [1] 이진 트리
- **이진 트리** : **차수(Degree)가 `2` 이하인 노드들로 구성된 트리**

<br>

#### [2] Preorder Traversal(전위 순회)
- **Preorder Traversal(전위 순회)** : **Root → Left → Right 순으로 운행하며 노드들을 찾아가는 방법**

<br>

#### [3] Inorder Traversal(중위 순회)
- **Inorder Traversal(중위 순회)** : **Left → Root → Right 순으로 운행하며 노드들을 찾아가는 방법**

<br>

#### [4] Postorder Traversal(후위 순회)
- **Postorder Traversal(후위 순회)** : **Left → Right → Root 순으로 운행하며 노드들을 찾아가는 방법**

<br>

#### [5] 수식의 표기법
- **젼위 표기법(PreFix)** : **연산자 → Left → Right**, `+AB`
- **중위 표기법(InFix)** : **Left → 연산자 → Right**, `A+B`
- **후위 표기법(PostFix)** : **Left → Right → 연산자**, `AB+`

<br>
<br>

### 55. 정렬(Sort)
#### [1] 삽입 정렬(Insertion Sort)
- **삽입 정렬(Insertion Sort)** : **이미 순서화된 파일에 새로운 하나의 레코드를 순서에 맞게 삽입시켜 정렬하는 방식**

- 평균과 최악의 경우 시간 복잡도 : `O(n`<sup>`2`</sup>`)`

<br>

#### [2] 선택 정렬(Selection Sort)
- **선택 정렬(Selection Sort)** : **최소값을 찾아 첫 번째 레코드 위치에 놓고, 나머지 중에서 최소값을 찾아 두 번째 레코드 위치에 놓는 과정을 반복하여 정렬하는 방식**

- 평균과 최악의 경우 시간 복잡도 : `O(n`<sup>`2`</sup>`)`

<br>

#### [3] 버블 정렬(Bubble Sort)
- **버블 정렬(Bubble Sort)** : **인접한 두 개의 레코드 키 값을 비교하여 그 크기에 따라 레코드 위치를 서로 교환하는 정렬 방식**

- 평균과 최악의 경우 시간 복잡도 : `O(n`<sup>`2`</sup>`)`

<br>

#### [4] 쉘 정렬(Shell Sort)
- **쉘 정렬(Shell Sort)** : **어떤 매개변수의 값으로 서브파일을 구성하고, 각 서브파일을 Insertion Sort 방식으로 순서 배열하는 과정을 반복하는 정렬 방식**

- 평균 시간 복잡도 : `O(n`<sup>`1.5`</sup>`)`
- 최악의 경우 시간 복잡도 : `O(n`<sup>`2`</sup>`)`

<br>

#### [5] 퀵 정렬(Quick Sort)
- **퀵 정렬(Quick Sort)** : **키를 기준으로 작은 값은 왼쪽, 큰 값은 오른쪽 서브 파일에 분해시키는 과정을 반복하는 정렬 반식**

- 평균 시간 복잡도 : `O(n log`<sub>`2`</sub>`n)`

- 최악의 경우 시간 복잡도 : `O(n`<sup>`2`</sup>`)`

<br>

#### [6] 힙 정렬(Heap Sort)
- **힙 정렬(Heap Sort)** : **완전 이진 트리(Complete Binary Tree)를 이용한 정렬 방식**

- 평균과 최악의 경우 시간 복잡도 : `O(n log`<sub>`2`</sub>`n)`

<br>

#### [7] 2-Way 합병 정렬(Merge Sort)
- **2-Way 합병 정렬(Merge Sort)** : **이미 정렬되어 있는 두 개의 파일을 한 개의 파일로 합병하는 과정을 반복하여 정렬하는 방식**

- 평균과 최악의 경우 시간 복잡도 : `O(n log`<sub>`2`</sub>`n)`

<br>

#### [8] 기수 정렬(Radix Sort)
- **기수 정렬(Radix Sort)** : **Queue를 이용하여 자릿수(Digit) 별로 정렬하는 방식**

- 평균과 최악의 경우 시간 복잡도 : `O(dn)` (d : 자릿수, n : 레코드 수)
