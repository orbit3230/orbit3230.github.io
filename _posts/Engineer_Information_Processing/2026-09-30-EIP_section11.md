# 정보처리기사
## 응용 SW 기초 기술 활용
### 128. 운영체제의 개념
#### [1] 운영체제(OS; Operating System)
- **운영체제** : **컴퓨터 시스템의 자원들을 효율적으로 관리하며, 컴퓨터를 편리하고 효과적으로 사용할 수 있도록 환경을 제공하는 여러 프로그램의 모임**

<br>

#### [2] 운영체제의 목적
- **처리 능력(Throughput)** : 일정 시간 내에 시스템이 처리하는 일의 양

- **반환 시간(Turn Around Time)** : 작업을 의뢰한 시간부터 처리가 완료될 떄까지 걸린 시간

- **사용 가능도(Availability)** : 사용할 필요가 있을 때 즉시 사용 가능한 정도

- **신뢰도(Reliability)** : 주어진 문제를 정확하게 해결하는 정도

<br>
<br>

### 129. 운영체제의 종류
#### [1] Windows
- **Windows** : **1990년대 마이크로소프트(Microsoft) 사가 개발한 운영체제**

- 특징
  - **그래픽 사용자 인터페이스(GUI; Graphical User Interface)**
  - **선점형 멀티태스킹(Preemptive Multi-tasking)**
  - **PnP(Plug and Play)**
  - **OLE(Object Linking and Embedding)**
  - **255자의 긴 파일명**
  - **Single-User 시스템**

<br>

#### [2] UNIX
- **UNIX** : **1960년대 AT&T 벨 연구소, MIT, General Electric이 공동 개발한 운영체제**

<br>

#### [3] UNIX 시스템의 구성

|구성 요소|설명|
|:---:|:---:|
|커널(Kernel)|하드웨어를 보호하고, 프로그램과 하드웨어 간의 인터페이스 역할을 담당|
|쉘(Shell)|사용자의 명령어를 인식하여 프로그램을 호출하고 명령을 수행하는 명령어 해석기|
|유틸리티 프로그램(Utility Program)|응용 프로그램을 처리하는 데 사용|

<br>

#### [4] LINUX
- **LINUX** : **1991년 리누스 토발즈(Linus Torvalds)가 UNIX를 기반으로 개발한 운영체제**

<br>

#### [5] MacOS
- **MacOS** : **1980년대 애플(Apple) 사가 UNIX를 기반으로 개발한 운영체제**

<br>

#### [6] Android
- **Android** : **구글(Google) 사에서 개발한 모바일 운영체제**

<br>

#### [7] iOS
- **iOS** : **애플(Apple) 사에서 개발한 모바일 운영체제**

<br>
<br>

### 130. 기억장치 관리
#### [1] 반입(Fetch) 전략
- **반입 전략** : **보조기억장치에 보관중인 프로그램이나 데이터를 언제 주기억장치로 적재할 것인지를 결정하는 전략**

|기법|내용|
|:---:|:---:|
|요구 반입(Demand Fetch)|참조를 요구할 때 적재하는 방법|
|예측 반입(Predictive Fetch)|미리 예상하여 적재하는 방법|

<br>

#### [2] 배치(Placement) 전략
- **배치 전략** : **새로 반입되는 프로그램이나 데이터를 주기억장치의 어디에 위치시킬 것인지를 결정하는 전략**

|기법|내용|
|:---:|:---:|
|최초 적합(First Fit)|들어갈 수 있는 크기의 빈 영역 중에서 첫 번째 분할 영역에 배치|
|최적 적합(Best Fit)|들어갈 수 있는 크기의 빈 영역 중에서 단편화를 가장 작게 남기는 분할 영역에 배치|
|최악 적합(Worst Fit)|들어갈 수 있는 크기의 빈 영역 중에서 단편화를 가장 크게 남기는 분할 영역에 배치|

<br>

#### [4] 교체(Replacement) 전략
- **교체 전략** : **이미 사용되고 있는 영역 중에서 어느 영역을 교체하여 사용할 것인지를 결정하는 전략**

- 종류 : FIFO, OPT, LRU, LFU, NUR, SCR 등

<br>
<br>

### 131. 가상기억장치 구현 기법
#### [1] 가상기억장치(Virtual Memory)
- **가상기억장치** : **보조기억장치의 일부를 주기억장치처럼 사용하는 것**

<br>

#### [2] 페이징(Paging) 기법
- **페이징 기법** : **프로그램과 주기억장치의 영역을 동일한 크기로 나눈 후 페이지 단위로 관리하며 적재하는 기법**

<br>

#### [3] 세그멘테이션(Segmentation) 기법
- **세그멘테이션 기법** : **프로그램을 다양한 크기의 논리적인 단위로 나눈 후 주기억장치에 적재시켜 실행시키는 기법**

<br>
<br>

### 132. 페이지 교체 알고리즘
#### [1] 페이지 교체 알고리즘
- **페이지 교체 알고리즘** : **페이지 부재(Page Fault)가 발생하면 어떤 페이지 프레임을 선택하여 교체할 것인지를 결정하는 알고리즘**

<br>

#### [2] OPT(OPTimal replacement, 최적 교체)
- **OPT** : **앞으로 가장 오랫동안 사용하지 않을 페이지를 교체하는 이상적인 알고리즘**

<br>

#### [3] FIFO(First In First Out)
- **FIFO** : **가장 먼저 들어와서 가장 오래 있었던 페이지를 교체하는 알고리즘**

<br>

#### [4] LRU(Least Recently Used)
- **LRU** : **최근에 가장 오랫동안 사용하지 않은 페이지를 교체하는 알고리즘**

<br>

#### [5] LFU(Least Frequently Used)
- **LFU** : **사용 빈도(참조 횟수)가 가장 낮은 페이지를 교체하는 알고리즘**

<br>

#### [6] NUR(Not Used Recently)
- **NUR** : **LRU와 비슷하지만, 최근에 사용하지 않은 페이지 중에서 교체하는 알고리즘**

<br>

#### [7] SCR(Second Chance Replacement)
- **SCR** : **FIFO 알고리즘의 단점을 보완하기 위해, 가장 오랫동안 주기억장치에 있던 페이지 중 자주 사용되는 페이지의 교체를 방지하기 위한 기법**

<br>
<br>

### 133. 가상기억장치 기타 관리 사항
#### [1] 페이지 관리
- 페이지 크기가 작을 경우
  - 장점 : 페이지 단편화 감소, 페이지 교체 시간 감소
  - 단점 : 페이지 맵 테이블 크기 증가, 매핑 속도 감소, 입·출력 시간 증가

- 페이지 크기가 큰 경우
  - 장점 : 페이지 맵 테이블 크기 감소, 매핑 속도 증가, 입·출력 시간 감소
  - 단점 : 페이지 단편화 증가, 페이지 교체 시간 증가

<br>

#### [2] Locality
- **지역성(Locality)** : **프로세스가 실행되는 동안 주기억장치를 참조할 때 일부 페이지만 집중적으로 참조하는 성질이 있다는 이론**

- Locality의 종류
  - **시간 구역성(Temporal Locality)** : 하나의 페이지를 집중적으로 액세스하는 현상 (예 : 반복문, 변수 참조)
  - **공간 구역성(Spatial Locality)** : 일정 위치의 페이지를 집중적으로 액세스하는 현상 (예 : 배열, 순차 코드)

<br>

#### [3] 워킹 셋(Working Set)
- **워킹 셋(Working Set)** : **프로세스가 일정 시간동안 자주 참조하는 페이지들의 집합**

<br>

#### [4] 스래싱(Thrashing)
- **스래싱(Thrashing)** : **프로세스의 처리 시간보다 페이지 교체에 소요되는 시간이 더 많아지는 현상**

<br>
<br>

### 134. 프로세스의 개요
#### [1] 프로세스(Process)
- **프로세스** : **실행 중인 프로그램**

<br>

#### [2] PCB(Process Control Block)
- **PCB** : **운영체제가 프로세스에 대한 중요한 정보를 저장해 놓는 곳**

<br>

#### [3] 프로세스 상태 전이

|상태|내용|
|:---:|:---:|
|제출(Submit)|사용자가 작업을 시스템에 제출한 상태|
|접수(Hold)|작업이 디스크의 할당 위치에 저장된 상태|
|준비(Ready)|프로세스를 할당받기 위해 기다리고 있는 상태|
|실행(Run)|프로세스를 할당받아 실행되는 상태|
|대기(Wait)/블록(Block)|입·출력 처리가 필요하면 프로세스가 중단되고, 대기하고 있는 상태|
|종료(Terminated, Exit)|실행이 끝나고 프로세스 할당이 해제된 상태|

<br>

#### [4] 프로세스 상태 전이 관련 용어

|용어|내용|
|:---:|:---:|
|Dispatch|준비 상태에서 대기하고 있는 프로세스 중 하나가 프로세서를 할당 받아 실행 상태로 전이되는 과정|
|Wake Up|입·출력 작업이 완료되어 대기 상태에서 준비 상태로 전이 되는 과정|
|Spooling|한꺼번에 입·출력하기 위해 디스크에 저장하는 과정|
|교통량 제어기(Traffic Controller)|프로세스 상태에 대한 조사와 통보 담당|

<br>

#### [5] 스레드(Thread)
- **스레드** : **시스템의 여러 자원을 할당받아 실행하는 프로그램의 단위** 또는 **프로세스 내에서의 작업 단위**

<br>
<br>

### 135. 스케줄링
#### [1] 스케줄링(Scheduling)
- **스케줄링** : **시스템의 여러 자원을 해당 프로세스에게 할당하는 작업**

<br>

#### [2] 비선점(Non-Preemptive) 스케줄링
- **비선점 스케줄링** : **이미 할당된 CPU를 다른 프로세스가 강제로 빼앗아 사용 할 수 없는 스케줄링 기법**

- 종류 : FCFS, SJF, 우선순위, HRN, 기한부 등

<br>

#### [3] 선점(Preemptive) 스케줄링
- **선점 스케줄링** : **우선 순위가 높은 다른 프로세스가 CPU를 강제로 빼앗아 사용할 수 있는 스케줄링 기법**

- 종류 : Round Robin, SRT, 선점 우선순위, 다단계 큐, 다단계 피드백 큐 등  

<br>
<br>

### 136. 주요 스케줄링 알고리즘
#### [1] FCFS(First Come First Serve)
- **FCFS** : **준비상태 큐에 도착한 순서에 따라 차례로 CPU를 할당하는 기법**

<br>

#### [2] SJF(Shortest Job First)
- **SJF** : **준비상태 큐에서 실행 시간이 가장 짧은 프로세스에게 먼저 CPU를 할당하는 기법**

<br>

#### [3] HRN(Highest Response-ratio Next)
- **HRN** : **대기 시간과 서비스(실행) 시간을 이용하는 기법**

- 우선순위 계산식 = `(대기 시간 + 서비스 시간) / 서비스 시간`

<br>

#### [4] RR(Round Robin)
- **RR** : **각 프로세스의 시간 할당량(Time Slice, Quantum) 동안만 실행한 후 완료 여부와 관계없이 다음 프로세스에게 CPU를 넘겨주는 기법**

<br>

#### [5] SRT(Shortest Remaining Time)
- **SRT** : **현재 실행중인 프로세스의 남은 시간과 새로 도착한 프로세스의 실행 시간을 비교하여 가장 짧은 실행 시간을 요구하는 프로세스에게 CPU를 할당하는 기법**

<br>
<br>

### 137. 환경 변수
#### [1] 환경 변수(Environment Variable)
- **환경 변수** : **시스템 소프트웨어의 동작에 영향을 미치는 동적인 값들의 모임**

<br>

#### [2] Windows의 주요 환경 변수

|환경 변수|설명|
|:---:|:---:|
|`%APPDATA%`|설치된 프로그램의 필요 데이터가 저장된 폴더|
|`%HOMEPATH%`|로그인한 계정의 기본 폴더|
|`%PATH%`|실행 파일을 찾는 경로|
|`%PROGRAMFILES%`|기본 프로그램의 설치 폴더|
|`%SYSTEMDRIVE%`|Windows가 부팅된 드라이브|
|`%SYSTEMROOT%`|부팅된 운영체제가 들어있는 폴더|
|`%USERNAME%`|로그인한 계정 이름|

<br>

#### [3] Linux의 주요 환경 변수
- UNIX나 LINUX에서 모든 환경 변수와 값을 표시하려면, `set`, `env`, `printenv`, `setenv` 명령어를 사용

|환경 변수|설명|
|:---:|:---:|
|`$DISPLAY`|현재 X 윈도 디스플레이 위치|
|`$HOME`|사용자의 홈 디렉터리|
|`$LANG`|시스템의 언어 설정|
|`$PATH`|실행 파일을 찾는 경로|
|`$PWD`|현재 작업 디렉터리|
|`$USER`|사용자 계정 이름|

<br>
<br>

<br>

- `chmod 000 filename`
  - `000` ~ `777`까지 8진수로 권한을 설정. (`사용자`, `그룹`, `기타 사용자` 순서로, `rwx`)

- `chmod u+r filename`
  - `u` : 사용자, `g` : 그룹, `o` : 기타 사용자, `a` : 모두
  - `+` : 권한 추가, `-` : 권한 제거, `=` : 권한 설정
  - `r` : 읽기 권한, `w` : 쓰기 권한, `x` : 실행 권한

<br>
<br>

### 139. 인터넷
#### [1] 인터넷(Internet)
- **인터넷** : **전 세계 수많은 컴퓨터와 네트워크들이 연결된 광범위한 컴퓨터 통신망**

<br>

#### [2] IP 주소(IP Address)
- **IP 주소** : **인터넷에 연결된 모든 컴퓨터 자원을 구분하기 위한 고유한 주소**

- IP 주소 5계층
  - **A Class** : 국가나 대형 통신망에 사용 (`0` ~ `127`), `2`<sup>`24`</sup> = `16,777,216` 개의 호스트 사용 가능

  - **B Class** : 중대형 통신망에 사용 (`128` ~ `191`), `2`<sup>`16`</sup> = `65,536` 개의 호스트 사용 가능

  - **C Class** : 소규모 통신망에 사용 (`192` ~ `223`), `2`<sup>`8`</sup> = `256` 개의 호스트 사용 가능

  - **D Class** : 멀티캐스트에 사용 (`224` ~ `239`)

  - **E Class** : 실험용으로 예약

<br>

#### [3] 서브네팅(Subnetting)
- **서브네팅** : **할당된 네트워크 주소를 다시 여러 개의 작은 네트워크로 나누어 사용하는 것**

- **서브넷 마스크** : **4Byte의 IP 주소 중 네트워크 주소와 호스트 주소를 구분하기 위한 비트**

- 서브네팅 예
  - (1) `192.168.1.0/24` 네트워크를 FLSM 방식을 이용하여 3개의 Subnet으로 나누고자 한다면,

  - (2) 나눌 네트워크 수(3개)에 필요한 최소 비트를 할당(2<sup>2</sup> = 4개이므로, 2비트 필요)

  - (3) 따라서 네트워크 개수 = `4`, 호스트 개수 = `2`<sup>`6`</sup> - `2` = `64`개

  - (4) 여기서 나눠진 네트워크 별 첫 번째 주소는 **네트워크 주소**, 마지막 주소는 **브로드캐스트 주소**로 사용

  - (5) 따라서 호스트 개수 = `2`<sup>`6`</sup> - `2` = `62`개

- 만약 IP 주소와 서브넷 마스크가 주어진 경우 해당 IP 주소의 네트워크 주소(네트워크의 시작 주소)를 알고 싶다면, IP 주소와 서브넷 마스크를 비트 단위로 AND 연산을 수행하면 된다.  

<br>

#### [4] IPv6(Internet Protocol version 6)
- **IPv6** : **IPv4의 주소 부족 문제를 해결하기 위해 개발된 128비트의 긴 주소 체계**

<br>

#### [5] IPv6의 구성
- 16비트씩 8부분, 총 128비트로 구성되어 있다.

- 각 부분을 16진수로 표현하고, 콜론(`:`)으로 구분한다.

- 다음과 같이 세 가지 주소 체계로 나누어진다.
  - 유니캐스트(Unicast) : 1:1 통신
  - 멀티캐스트(Multicast) : 1:N 통신
  - 애니캐스트(Anycast) : 1:1 통신, 가장 가까운 노드에 전달

<br>

#### [6] 도메인 네임(Domain Name)
- **도메인 네임** : **숫자로 된 IP 주소를 문자 형태로 표현한 것**

<br>
<br>

### 140. OSI 참조 보델
#### [1] OSI 참조 모델(OSI Reference Model)
- **OSI 참조 모델** : **ISO(국제 표준화 기구)에서 제안한 통신 규약(Protocol)

<br>

- 하위 계층 : 물리 계층 → 데이터 링크 계층 → 네트워크 계층 → 전송 계층
- 상위 계층 : 세션 계층 → 표현 계층 → 응용 계층

<br>

#### [2] 응용 계층(Application Layer)
- **응용 계층** : **응용 프로그램이 OSI 환경에 접근할 수 있도록 서비스를 제공**

<br>

#### [3] 표현 계층(Presentation Layer)
- **표현 계층** : **응용 계층으로 부터 받은 데이터를 세션 계층에 보내기 전에 통신에 적당한 형태로 변환하는 계층**

<br>

#### [4] 세션 계층(Session Layer)
- **세션 계층** : **송·수신 측 간의 관련성을 유지하고 대화 제어를 담당하는 계층**

- 대화의 생성, 관리, 종료를 위해 토큰을 사용한다.

<br>

#### [5] 전송 계층(Transport Layer)
- **전송 계층** : **논리적 안정과 균일한 데이터 전송 서비스를 제공함으로써, End-to-End 간에 투명한 데이터 전송을 제공하는 계층**

- End-to-End 간의 전송 연결 설정, 데이터 전송, 연결 해제 기능을 한다.

- 주소 설정, 다중화(분할 및 재조립), 오류 제어, 흐름 제어를 수행

- 표준 : TCP, UDP

- 관련 장비 : 게이트웨이

<br>

#### [6] 네트워크 계층(Network Layer)
- **네트워크 계층** : **네트워크 연결을 관리하는 기능과 데이터의 교환 및 중계 기능을 제공하는 계층**

- 네트워크 연결을 설정, 유지, 해제하는 기능을 한다.

- 경로 설정(Routing), 데이터 교환 및 중계, 트래픽 제어, 패킷 정보 전송을 수행

- 표준 : X.25, IP 등

- 관련 장비 : 라우터

<br>

#### [7] 데이터 링크 계층(Data Link Layer)
- **데이터 링크 계층** : **두 개의 인접한 개방 시스템들 간에 신뢰성 있고 효율적인 정보 전송을 할 수 있도록 연결 설정과 유지 및 종료를 담당하는 계층**

- 속도 차이 해결 및 프레임의 동기화 기능, 오류의 검출과 회복을 위한 오류 제어 기능을 한다.

- 표준 : HDLC, LAPB, LLC, MAC, LAPD, PPP 등

- 관련 장비 : 랜카드, 브리지, 스위치

<br>

#### [8] 물리 계층(Physical Layer)
- **물리 계층** : **두 장치 간의 실제 접속과 절단 등의 규칙을 정의하는 계층**

- 표준 : RS-232C, X.21 등

- 관련 장비 : 리피터, 허브

<br>
<br>

### 141. 네트워크 관련 장비
#### [1] 네트워크 인터페이스 카드(NIC; Network Interface Card)
- **NIC** : **컴퓨터와 컴퓨터 또는 컴퓨터와 네트워크를 연결하는 장치**

<br>

#### [2] 허브(Hub) - Layer 1
- **허브** : **회선을 통합하여 관리하는 장치**

<br>

#### [3] 리피터(Repeater) - Layer 1
- **리피터** : **수신한 신호를 재생시키거나 증폭하여 전송하는 장치**

<br>

#### [4] 브리지(Bridge) - Layer 2
- **브리지** : **LAN과 LAN을 연결하거나 LAN 안에서의 컴퓨터 그룹을 연결하는 장치**

<br>

#### [5] 스위치(Switch) - Layer 2
- **스위치** : **브리지와 같이 LAN과 LAN을 연결하여 훨씬 더 큰 LAN을 구성하는 장치**

<br>

#### [6] 라우터(Router) - Layer 3
- **라우터** : **브리지와 같이 LAN과 LAN을 연결하되, 데이터 전송의 최적 경로를 선택하는 기능이 추가된 장치**

<br>

#### [7] 게이트웨이(Gateway) - Layer 4
- **게이트웨이** : **서로 다른 프로토콜 구조를 가진 네트워크를 연결하는 장치**

<br>
<br>

### 142. TCP/IP
#### [1] 프로토콜(Protocol)
- **프로토콜** : **데이터 교환을 원활하게 수행할 수 있도록 표준화시켜 놓은 통신 규약**

- 프로토콜의 기본 요소
  - 구문(Syntax) : 데이터 형식, 부호화, 신호 레벨 등을 규정
  - 의미(Semantics) : 정확한 정보 전송을 위한 협조 사항과 오류 관리를 위한 제어 정보를 규정
  - 시간(Timing) : 통신 속도, 메시지의 순서 제어 등을 규정

  <br>

#### [2] TCP/IP(Transmission Control Protocol / Internet Protocol)
- **TCP/IP** : **서로 다른 기종의 컴퓨터들이 데이터를 주고받을 수 있도록 하는 표준 프로토콜**

|프로토콜|내용|
|:---:|:---:|
|TCP(Transmission Control Protocol)|OSI 7계층의 전송 계층(Layer 4)에 해당<br>가상 회선 방식을 기반으로 하는 연결형 서비스<br>패킷의 다중화, 순서 제어, 오류 제어, 흐름 제어 기능을 제공|
|IP(Internet Protocol)|OSI 7계층의 네트워크 계층(Layer 3)에 해당<br>데이터그램 방식 기반의 비연결형 서비스<br>패킷의 분해/조립, 주소 지정, 경로 선택 기능을 제공|

<br>

#### [3] TCP/IP의 구조

|OSI|TCP/IP|기능|
|:---:|:---:|:---:|
|응용 계층<br>표현 계층<br>세션 계층|응용 계층|응용 프로그램 간의 데이터 송·수신 제공|
|전송 계층|전송 계층|호스트들 간의 신뢰성 있는 통신 제공|
|네트워크 계층|인터넷 계층|데이터 전송을 위한 주소 지정, 경로 설정을 제공|
|데이터 링크 계층<br>물리 계층|네트워크 액세스 계층|실제 데이터(프레임)를 송·수신하는 역할|

<br>

#### [4] 응용 계층의 주요 프로토콜

|프로토콜|내용|
|:---:|:---:|
|FTP(File Transfer Protocol)|원격 파일 전송 프로토콜|
|SMTP(Simple Mail Transfer Protocol)|전자 우편을 교환하는 서비스|
|TELNET|컴퓨터 원격 접속 서비스|
|SNMP(Simple Network Management Protocol)|TCP/IP의 네트워크 관리 프로토콜|
|DNS(Domain Name System)|도메인 네임을 IP 주소로 매핑(Mapping)하는 시스템|
|HTTP(Hyper Text Transfer Protocol)|웹에서 HTML 문서를 송수신하기 위한 표준 프로토콜|
|MQTT(Message Queuing Telemetry Transport)|발행-구독 기반의 메시징 프로토콜|

<br>

#### [5] 전송 계층의 주요 프로토콜

|프로토콜|내용|
|:---:|:---:|
|TCP(Transmission Control Protocol)|양방향 연결형 서비스 제공<br>가상 회선 연결 형태의 서비스 제공<br>스트림 위주의 전달(패킷 단위)<br>신뢰성있는 경로를 확립<br>순서 제어, 오류 제어, 흐름 제어의 기능<br>투명성이 보장되는 통신을 제공|
|UDP(User Datagram Protocol)|비연결형 서비스 제공<br>상대적으로 단순한 헤더 구조로 오버헤드가 적고 전송 속도가 빠름<br>실시간 전송에 유리|
|RTCP(Real-time Transport Control Protocol)|RTP(Real-time Transport Protocol) 패킷의 전송 품질을 제어하기 위한 제어 프로토콜|

#### [6] 인터넷 계층의 주요 프로토콜

|ARP(Address Resolution Protocol)|IP 주소를 MAC 주소로 변환하는 프로토콜|
|RARP(Reverse Address Resolution Protocol)|MAC 주소를 IP 주소로 변환하는 프로토콜|

<br>

#### [7] 네트워크 액세스 계층의 주요 프로토콜

|RS-232C|공중 전화 교환망(PSTN)을 통한 DTE와 DCE 간의 인터페이스를 제공하는 프로토콜|

### 143. 네트워크 관련 신기술
#### [1] 네트워크 관련 신기술

|신기술|내용|
|:---:|:---:|
|IoT(Internet of Things, 사물 인터넷)|다양한 사물들을 인터넷으로 서로 연결한 서비스 기반 기술|
|M2M(Machine to Machine)|무선 통신을 이용한 기계와 기계 사이의 통신|
|모바일 컴퓨팅(Mobile Computing)|휴대형 기기로 이동하면서 업무를 처리할 수 있는 환경|
|클라우드 컴퓨팅(Cloud Computing)|중앙 컴퓨터에 각종 컴퓨팅 자원을 두고 어디서나 인터넷을 통해 작업을 수행할 수 있는 가상화된 환경|
|그리드 컴퓨팅(Grid Computing)|지리적으로 분산되어 있는 컴퓨터를 초고속 인터넷망으로 연결하여 공유함으로써 하나의 고성능 컴퓨터처럼 활용하는 기술|
|모바일 클라우드 컴퓨팅(MCC; Mobile Cloud Computing)|클라우드 서비스를 이용하여 모바일 기기로 클라우드 컴퓨팅 인프라를 구성하는 ICT 기술|
|인터클라우드 컴퓨팅(Inter-Cloud Computing)|각기 다른 클라우드 서비스나 자원을 연결하는 기술|
|메시 네트워크(Mesh Network)|특수 목적을 위한 대규모 디바이스 네트워크를 구성하는 기술|
|와이선(Wi-SUN)|사물 인터넷(IoT) 서비스를 위한 저전력 장거리(LPWA) 통신 기술|
|NDN(Named Data Networking)|콘텐츠 자체 정보와 라우터 기능만으로 데이터 전송을 수행하는 기술|
|NGN(Next Generation Network)|유선망 기반의 차세대 통신망|
|SDN(Software Defined Network)|네트워크를 컴퓨터처럼 모델링하여 소프트웨어로 네트워킹을 가상화하여 제어하고 관리하는 네트워크|
|NFC(Near Field Communication)|고주파(HF)를 이용한 근거리 무선 통신 기술|
|UWB(Ultra Wide Band)|짧은 거리에서 많은 양의 디지털 데이터를 낮은 전력으로 전송하는 무선 통신 기술|
|피코넷(Piconet)|여러 개의 독립된 통신 장치가 블루투스나 UWB를 이용하여 통신망을 형성하는 기술|
|WBAN(Wireless Body Area Network)|웨어러블 또는 몸에 심는 형태의 센서나 기기를 무선으로 연결하는 기술|
|GIS(Geographic Information System)|지리적인 자료를 수집·저장·분석·출력할 수 있는 컴퓨터 응용 시스템|
|USN(Ubiquitous Sensor Network)|각종 센서로 수집한 정보를 무선으로 수집할 수 있도록 구성한 네트워크|
|SON(Self Organizing Network)|주변 상황에 맞추어 스스로 망을 구성하는 네트워크|
|애드-혹 네트워크(Ad-hoc Network)|재난 현장과 같이 유선망을 구축할 수 없는 환경에서 모바일 호스트 만을 이용하여 구성한 임시 네트워크|
|네트워크 슬라이싱(Network Slicing)|하나의 물리적인 코어 네트워크 인프라를 독립된 다수의 가상 네트워크로 분리하는 기술|
|저전력 블루투스 기술(BLE; Bluetooth Low Energy)|동일하게 2.4GHz 대역을 사용하지만, 대기 상태에서 절전모드를 유지하는 기술|
|파장 분할 다중화(WDM; Wavelength Division Multiplexing)|광섬유를 이용한 통신 기술의 하나로, 파장이 서로 다른 복수의 신호를 보내 간섭 없이 여러 단말기가 동시에 통신 회선을 사용할 수 있도록 하는 기술|
|소프트웨어 정의 데이터 센터(SDDC; Software Defined Data Center)|데이터 센터의 모든 자원을 가상화하여 소프트웨어 조작만으로 관리 및 제어되는 데이터 센터|
|개방향 링크드 데이터(LOD; Linked Open Data)|누구나 사용할 수 있도록 웹상에 공개된 연계 데이터|
|SSO(Single Sign-On)|한 번의 로그인으로 개인이 가입한 모든 사이트를 이용할 수 있게 해주는 시스템|

### 144. 네트워크 구축
#### [1] 네트워크(Network)
- **네트워크** : **두 대 이상의 컴퓨터를 연결하여 자원을 공유하는 것**

<br>

#### [2] 성형(Star, 중앙 집중형)
- **성형(Star)** : **중앙에 중앙 컴퓨터가 있고, 이를 중심으로 단말장치들이 연결되는 중앙 집중식의 네트워크 구성 형태**

<br>

#### [3] 링형(Ring, 루프형)
- **링형(Ring)** : **컴퓨터와 단말장치들을 서로 이웃하는것끼리 연결시킨 포인트 투 포인트 방식의 구성 형태**

<br>

#### [4] 버스형(Bus)
- **버스형(Bus)** : **한 개의 통신 회선에 여러 대의 단말장치가 연결되어 있는 형태**

<br>

#### [5] 계층형(Tree, 분산형)
- **계층형(Tree)** : **중앙 컴퓨터와 일정 지역의 단말장치까지는 하나의 통신 회선으로 연결시키고, 이웃하는 단말장치는 일정 지역 내에 설치된 중간 단말장치로부터 다시 연결시키는 형태**

<br>

#### [6] 망형(Mesh)
- **망형(Mesh)** : **모든 지점의 컴퓨터와 단말장치를 서로 연결한 형태**

<br>

#### [7] 네트워크의 분류

|분류|내용|
|:---:|:---:|
|LAN(Local Area Network)|근거리 통신망으로, 데이터의 전송 속도가 빠르고 에러 발생율이 낮음|
|WAN(Wide Area Network)|광역 통신망으로, 국가와 국가 또는 대륙과 대륙을 연결하는 통신망|

<br>

#### [8] LAN의 표준안
- 802.11의 버전

|버전|내용|
|:---:|:---:|
|802.11|2.4GHz 대역 전파와 CSMA/CA 기술을 사용해 최대 2Mbps의 속도|
|802.11a|5GHz 대역 전파와 OFDM 기술을 사용해 최대 54Mbps의 속도|
|802.11b|2.4GHz 대역으로 11Mbps의 속도|
|802.11e|QoS(Quality of Service) 기능을 추가|
|802.11g|2.4GHz 대역으로 54Mbps의 속도|
|802.11n|2.4GHz와 5GHz 대역을 모두 사용하며, 최대 600Mbps의 속도|

<br>

#### [9] NAT(Network Address Translation, 네트워크 주소 변환)
- **NAT** : **한 개의 정식 IP 주소에 대량의 가상 사설 IP 주소를 할당 및 연결하는 기능**

### 145. 경로 제어 / 트래픽 제어
#### [1] 경로 제어(Routing)
- **경로 제어** : **전송 경로 중에서 최적 패킷 교환 경로를 결정하는 기능**

<br>

#### [2] 경로 제어 프로토콜(Routing Protocol)
- **IGP(Interior Gateway Protocol)** : **하나의 자율 시스템(AS) 내의 라우팅에 사용되는 프로토콜**
  - **RIP(Routing Information Protocol)**
    - 거리 벡터 라우팅 프로토콜 이라고도 함
    - Bellman-Ford 알고리즘 기반
    - 최대 홉(Hop) 수를 15로 제한하므로, 소규모 네트워크에 적합
    - 라우징 정보를 30초마다 모든 라우터에 전송하여 이상 상태를 감지

  - **OSPF(Open Shortest Path First)**
    - RIP의 단점을 해결한 대규모 네트워크에 적합한 라우팅 프로토콜
    - 노드 간의 거리 정보, 링크 상태 정보를 실시간으로 반영
    - Dijkstra 알고리즘 기반
    - 라우팅 정보에 변화가 생길 경우 변화된 정보만 다른 라우터에 전송

<br>

- **EGP(Exterior Gateway Protocol)** : **자율 시스템(AS) 간의 라우팅, 즉 게이트웨이 간의 라우팅에 사용되는 프로토콜**
  
- **BGP(Border Gateway Protocol)** : **EGP의 단점을 보완한 프로토콜로, 초기에만 라우팅 테이블을 교환하고 이후에는 변화된 정보만을 교환**

<br>

#### [3] 트래픽 제어
- **트래픽 제어** : **전송되는 패킷의 흐름 또는 그 양을 조절하는 기능**

- 트래픽 제어의 종류
  - 흐름 제어
  - 폭주(혼잡) 제어
  - 교착상태 방지

<br>

#### [4] 흐름 제어(Flow Control)
- **흐름 제어** : **송·수신 측 사이에 전송되는 패킷의 양이나 속도를 규제하는 기능**

|기법|내용|
|:---:|:---:|
|정지-대기(Stop and Wait)|수신 측의 확인 신호(ACK)를 받은 후에 다음 패킷을 전송하는 방식<br>한 번에 하나의 패킷만을 전송|
|슬라이딩 윈도우(Sliding Window)|확인 신호(ACK)를 이용하여 송신 데이터의 양을 조절하는 방식<br>ACK 없이도 보낼 수 있는 패킷의 최대치를 약속하는데, 이를 윈도우(Window)라고 함<br>윈도우 크기(Window Size)는 ACK과 NAK의 수신 여부에 따라 변화|

<br>

#### [5] 폭주 제어(Congestion Control)
- **폭주 제어** : **네트워크 내의 패킷 수를 조절하여 혼잡 상태를 방지하는 기능**

|기법|내용|
|:---:|:---:|
|느린 시작(Slow Start)|윈도우의 크기를 1, 2, 4, 8, ...과 같이 지수적으로 증가시키는 방식<br>임계 값(Threshold)에 도달하면 혼잡 회피 단계로 넘어감|
|혼잡 회피(Congestion Avoidance)|혼잡 상태로 간주하고 윈도우의 크기를 1씩 선형적으로 증가시켜 혼잡을 예방하는 방식|

<br>
<br>

### 151. 회복 / 병행제어
#### [1] 회복(Recovery)
- **회복** : **데이터베이스가 손상되었을 때 손상되기 이전의 정상 상태로 복구하는 작업**

- 회복 기법의 종류

|회복 기법|설명|
|:---:|:---:|
|연기 갱신 기법(Deferred Update)|트랜잭션이 성공적으로 완료될 때까지 데이터베이스에 대한 실질적인 갱신을 연기하는 방법<br>Redo 작업만 가능|
|즉시 갱신 기법(Immediate Update)|트랜잭션이 데이터를 갱신하면 트랜잭션이 부분 완료되기 전이라도 즉시 실제 데이터베이스에 반영하는 기법<br>Redo와 Undo 모두 가능|
|그림자 페이지 대체 기법(Shadow Paging)|각 페이지마다 복사본인 그림자 페이지를 별도 보관해 놓고, 장애가 발생하여 트랜잭션을 Rollback 시킬 때에는 실제 페이지 부분을 그림자 페이지로 대체하여 회복|
|검사점 기법(Check Point)|특정 단계에서 재실행할 수 있도록 검사점을 로그에 보관해 두고, 검사점부터 회복 작업을 수행|

<br>

#### [2] 병행제어(Concurrency Control)
- **병행제어** : **동시에 실행되는 트랜잭션 간의 상호 작용을 제어하는 것**

- 병행제어 기법의 종류

|병행제어 기법|설명|
|:---:|:---:|
|로킹(Locking)|트랜잭션들이 Lock을 요청해서 Lock이 허락되어야만 로킹 단위를 액세스할 수 있도록 하는 기법|
|타임 스탬프 순서(Time Stamp Ordering)|실행을 시작하기전에 시간표(Time Stamp)를 부여하여 트랜잭션 작업을 수행하는 기법|
|최적 병행수행|Read Only 트랜잭션이 대부분인 경우, 충돌률이 매우 낮아서 일관성 있는 결과를 얻을 수 있는 기법|
|다중 버전 기법|다중 버전 타임 스탬프 기법으로, 갱신될 때 마다 버전을 부여하여 관리하는 기법|

<br>

### 152. 교착상태
#### [1] 교착상태(Deadlock)
- **교착상태** : **서로 다른 프로세스가 점유하고 있는 자원을 요구하며 무한정 기다리는 현상**

<br>

#### [2] 교착상태 발생의 필요 충분 조건

|조건|설명|
|:---:|:---:|
|상호 배제(Mutual Exclusion)|한 번에 한 개의 프로세스만이 공유 자원을 사용|
|점유와 대기(Hold and Wait)|최소한 하나의 자원을 점유하고 있으면서 다른 프로세스에 할당된 자원을 추가로 점유하기 위해 대기하는 프로세스가 존재|
|비선점(Non-preemption)|다른 프로세스에 할당된 자원을 강제로 빼앗을 수 없음|
|순환 대기(Circular Wait)|공유 자원과 해당 자원을 사용하기 위해 대기하는 프로세스들이 원형으로 구성|

<br>

#### [3] 교착상태의 해결 방법

|기법|설명|
|:---:|:---:|
|예방 기법(Prevention)|사전에 시스템을 제어하는 방법|
|회피 기법(Avoidance)|교착상태가 발생한 가능성을 배제하기 않고 교착상태가 발생하면 적절히 피해가는 방법<br>주로 은행원 알고리즘(Banker's Algorithm)이 사용됨|
|발견 기법(Detection)|교착상태가 발생했는지 점검하는 방법|
|회복 기법(Recovery)|교착상태를 일으킨 프로세스를 종료하거나 자원을 회수하는 방법|
