# 한국사 퀴즈 서버

블로그 화면은 GitHub Pages, 문제·관리자 인증·풀이 통계는 별도의 Cloudflare Worker와 D1에서 처리합니다. 댓글 서버와 데이터베이스를 공유하지 않습니다.

## 연결 상태

2026-11-25에 전용 Worker와 D1을 배포하고 실제 응답을 확인했습니다. API는 `https://orbit-history-quiz.orbit3230.workers.dev`, D1은 `orbit-history-quiz`입니다. `AUTH_PEPPER`와 `SETUP_TOKEN`은 Cloudflare Secret에 등록되어 있으며 관리자 비밀번호는 소유자가 초기 설정 화면에서 직접 등록합니다. 최초 확인 시 문제와 분류는 모두 비어 있었습니다. 블로그 정적 페이지의 공개 반영은 커밋·푸시 후 별도로 진행됩니다.

## 배포

1. Cloudflare 소유자 계정으로 Wrangler에 로그인합니다. 무료 요금제를 유지하고 별도 유료 기능을 추가하지 않습니다.
2. `npx wrangler d1 create orbit-history-quiz`로 전용 DB를 생성합니다. 반환된 ID를 `wrangler.toml`의 `database_id`에 넣습니다.
3. `npx wrangler d1 migrations apply orbit-history-quiz --remote`로 초기 스키마와 그룹 변경을 순서대로 적용합니다. 새 DB와 기존 v20 DB 모두 이 경로를 사용합니다. 변경 전에는 `npx wrangler d1 export orbit-history-quiz --remote --output=<비공개 백업 경로>`로 백업합니다. `schema.sql`은 테스트용 최신 구조이며 마이그레이션 적용 전 운영 DB에 따로 실행하지 않습니다.
4. 각각 독립적으로 생성한 32바이트 이상의 무작위 비밀값을 `AUTH_PEPPER`, `SETUP_TOKEN` Secret으로 등록합니다. 예: `npx wrangler secret put AUTH_PEPPER`. 값을 소스·설정·로그·README에 넣지 않습니다.
5. `npx wrangler deploy`로 배포하고 `/status`, `/catalog`, `/groups`의 응답을 확인합니다. `_config.yml`의 `quiz.api_url`은 실제 Worker 주소와 같아야 합니다.
6. 블로그를 배포하거나 허용된 로컬 주소에서 실행합니다. 소유자만 `https://orbit3230.github.io/history-quiz/#setup=<초기설정키>`로 접속하여 원하는 비밀번호를 입력합니다. 키는 Git 또는 공개 메시지로 공유하지 않습니다. `#` 뒤의 값은 페이지 요청에 포함되지 않으며 앱이 즉시 주소에서 지웁니다. 등록 요청 때만 HTTPS로 서버에 보냅니다.
7. 최초 등록이 끝나면 `npx wrangler secret delete SETUP_TOKEN`으로 설정 키를 제거할 수 있습니다. 관리자 레코드가 존재하면 키가 남아 있어도 추가 등록이나 비밀번호 덮어쓰기를 거부합니다. 일반 접속에서는 비밀번호 팝업으로 인증합니다.

처음부터 누구나 비밀번호를 선점하도록 공개하지 않습니다. 최초 비밀번호는 소유자용 초기 설정 링크를 가진 사람만 등록할 수 있으며 DB의 단일 관리자 제약으로 동시 등록도 하나만 성공합니다. 비밀번호 원문은 저장하지 않습니다. 관리자 비밀번호는 분실 시 자동 복구되지 않습니다. 운영자 본인이 Cloudflare에서 인증 데이터와 세션을 안전하게 재설정해야 하며, 문제·통계 테이블은 삭제하지 않습니다.

`AUTH_PEPPER`는 계속 유지해야 합니다. 교체하면 기존 비밀번호 검증이 불가능합니다. 로컬 Secret 파일은 `.gitignore`로 제외하며 `quiz-service/` 전체는 Jekyll 결과에서 제외합니다. 서버 소스가 공개되어도 실제 비밀번호·Secret·세션 토큰·DB 데이터는 레포지토리에 포함하지 않습니다.

## 사용

- 첫 화면에서 문제 만들기 / 문제 풀기를 선택합니다.
- 만들기는 비밀번호 인증 → 그룹 생성 또는 선택 → 문제 생성 순서입니다. 그룹 이름은 1~60자이며 생성 순서대로 표시합니다. 같은 이름을 재요청하면 기존 그룹을 사용합니다. 그룹 안에서 연속 생성하면 그룹·시대·정답 종류를 유지합니다.
- 풀기도 그룹을 먼저 선택해야 합니다. 서버가 선택한 그룹으로 출제와 관리 목록을 제한하며, 그룹 변경 버튼으로 돌아갈 수 있습니다. 풀이의 시대 필터도 현재 그룹 안에서만 작동합니다. 시대와 정답 종류 항목은 여러 그룹에서 함께 사용합니다.
- 그룹 도입 전에 있던 문제는 ‘기존 문제’ 그룹으로 옮기고 문제·누적 정답·오답 기록을 그대로 보존합니다. 기존 문제가 없다면 자동 그룹을 만들지 않습니다. 삭제·이름 변경·문제 이동은 아직 제공하지 않습니다.
- 시대와 정답 종류 목록은 비어 있는 상태에서 시작합니다. 메뉴 전체 버튼이 열기 영역이며 마지막의 `+ 항목 추가`에서 이름을 입력합니다. 생성 ID 순서로 나열하고 같은 종류의 같은 이름은 중복 생성하지 않습니다.
- 키워드와 정답 입력 후 생성 또는 Enter를 누릅니다. 성공 시 키워드와 첫 정답 입력칸을 비우고 추가 정답 행은 제거합니다. 선택한 그룹·시대·첫 분류를 유지합니다. 한글 조합을 확정하는 Enter는 제출하지 않습니다.
- 관리 목록은 5개씩 조회하며 수정과 삭제를 제공합니다. 수정은 통계를 초기화하고 이전 버전의 미제출 답안을 무효화합니다. 삭제는 문제를 숨기는 방식이며 DB 기록을 보존합니다. 항목 이름은 30자, 키워드는 500자, 정답은 공백 포함 60자까지입니다.
- 풀이에서는 시대 → 키워드 → 통계와 화살표 → 정답 종류와 빈칸 순으로 표시합니다. 빈칸은 정답의 글자 수·단어별 간격을 나타냅니다. 한글 조합·붙여넣기·수정을 위해 하나의 실제 입력칸을 사용하고 위의 빈칸에 입력을 반영합니다.
- 채점은 Unicode NFC 정규화 후 비교합니다. 앞뒤 공백은 무시하고 연속 공백은 하나로 합칩니다. 단어 사이 공백, 문장부호 및 영문 대소문자는 구별합니다. 정답을 맞히면 초록색, 틀리면 빨간색과 실제 정답을 표시합니다.
- 타건음은 Web Audio로 짧게 합성하며 기본 꺼짐입니다. 소리 설정만 localStorage에 저장하고 외부 오디오 파일은 불러오지 않습니다. 미지원 환경에서도 풀이는 가능합니다. 입력 효과는 모션 감소 설정을 따릅니다.
- 전체 방문자의 풀이 횟수를 집계합니다. 같은 문제를 새로 받아 다시 풀면 새로운 풀이입니다. 고유 사용자 수나 개인별 성적이 아닙니다.

## 인증과 데이터

브라우저에서 개별 salt를 사용한 PBKDF2-SHA256 600,000회로 비밀번호 키를 만들고 HTTPS로 전송합니다. 서버는 Secret을 사용한 HMAC 검증값만 DB에 보관하며 상수 시간 검증을 사용합니다. 브라우저에서 생성한 키도 인증 비밀값이므로 로깅하지 않습니다. 관리자 세션은 256비트 무작위 토큰이고 DB에는 해시만 저장합니다. 토큰은 화면 메모리에만 유지하며 4시간 후 만료됩니다. 처음으로/로그아웃은 서버 세션도 폐기하고 새로고침하면 재인증이 필요합니다.

그룹·문제·분류의 쓰기와 관리자 목록 조회는 모두 서버 인증을 요구합니다. 공개 문제에는 정답 자체 대신 단어별 길이만 반환합니다. 채점 결과를 브라우저가 정해서 보낼 수 없습니다. 풀이마다 발급하는 토큰으로 한 번만 제출할 수 있고, DB 트리거가 통계를 원자적으로 갱신합니다. 같은 요청의 재시도는 재집계하지 않으며 다른 답으로 재제출하면 거절합니다. 문제 생성도 요청 ID로 중복 저장을 막습니다.

인증은 IP 기반 15분당 10회, 일반 요청은 분당 240회, 풀이 발급·채점은 각각 분당 80회로 제한합니다. IP 원문을 DB에 보관하지 않고 날짜별 HMAC 값으로 제한합니다. 출처 제한과 요청 제한은 완전한 봇 방어가 아니며 익명 통계에는 반복 참여가 포함될 수 있습니다. 만료 세션·요청 제한·오래된 풀이 토큰은 예약 작업으로 정리합니다. 문제와 누적 통계는 정리 대상이 아닙니다.

## 검사

Node.js 24 이상에서 `node test.mjs`를 실행합니다. 실제 SQLite 인메모리 DB로 최초 등록 보호, 로그인, 권한, 분류 순서, 문제 저장, 정답 비공개, 중복 채점 방지, 통계, 수정 충돌, 삭제, 요청 제한을 검사합니다. 운영 DB에 테스트 문제를 넣지 않습니다.

API: `GET /status`, `GET /catalog`, `GET /groups`, `POST /groups`, `POST /setup`, `/login`, `/logout`, `/categories`, `/questions`, `/delete`, `/next`, `/answer`, 관리자 `GET /manage?group=<그룹ID>&page=1`. `POST /questions`와 `/next`는 `group_id`를 필수로 받습니다.


## 복수 정답과 개인별 우선 출제 (2026-11-26)

- `POST /questions`는 `answers: [{type_id, answer}, ...]`를 받습니다. 순서대로 1~10개, 각 정답은 공백 포함 1~60자입니다. 정답 분류는 기존 `type` 목록을 함께 사용합니다. 기존 단일 정답 요청도 계속 허용하지만, 이전 화면에서 복수 정답 문제를 단일 정답으로 덮어쓰는 요청은 거절합니다.
- `GET /manage`에는 분류명까지 포함한 `answers`를 반환합니다. `POST /next`의 공개 `question.answers`에는 각 항목의 분류명과 단어별 길이만 포함하고 정답은 노출하지 않습니다.
- `POST /answer`는 입력 순서의 `answers: [문자열, ...]`를 받고 `results: [{type, correct, answer}, ...]`로 항목별 결과를 돌려줍니다. 모든 항목이 맞아야 전체 `correct`가 참입니다. 기존 트리거로 한 문제당 정답 또는 오답 1회만 집계합니다. 같은 요청 재전송은 중복 집계하지 않습니다.
- 새 화면은 `POST /next`에 무작위 256비트 `player` 식별자를 보냅니다. 서버는 이를 HMAC 처리해 풀이 토큰에 연결하고, 제출 시 `player_progress`에 해당 문제 버전의 최초 성공 여부를 원자적으로 반영합니다. 클라이언트가 성공 여부를 선언해서 기록을 바꿀 수 없습니다. 원본 식별자를 DB에 저장하거나 로그에 출력하지 않습니다.
- 출제 순서: 선택 그룹·시대의 미성공 문제 우선 → 같은 우선순위에서 직전 문제 회피 → 랜덤. 모든 문제를 한 번 이상 모두 맞히면 해당 범위 전체에서 랜덤입니다. 오답을 내도 이전 성공 기록을 지우지 않습니다. 문제 수정은 새 버전으로 취급합니다.
- 익명 식별자는 같은 사이트의 localStorage에 저장합니다. 기기 간 동기화·사용자 계정·개인별 성적 조회 기능은 없습니다. 저장소 이용이 불가능하면 메모리의 임시 식별자를 사용합니다. 기존 누적 통계는 보존하며 과거 익명 풀이를 특정 방문자의 기록으로 추정하지 않습니다.

`0002_multiple_answers.sql`은 기존 `answer`, 분류, 정답·오답 횟수를 변경하지 않고 복수 정답 저장 열과 방문자별 성공 기록을 추가합니다. 기존 단일 정답 행은 읽을 때 한 항목으로 변환합니다. 운영 DB를 백업한 뒤 `npx wrangler d1 migrations apply orbit-history-quiz --remote`, 이어서 서버 배포를 수행합니다. Secret은 변경하지 않습니다.

`node test.mjs`와 `node test-multiple.mjs`로 기존 기능, 복수 정답, 부분 채점, 중복 제출, 개인별 우선순위, 기존 데이터 이전을 검사합니다.


## 응답 속도 개선 (2026-11-26)

즉석 수정용 `GET /manage?group=<group_id>&id=<question_id>`는 기존 `/manage`와 동일한 관리자 세션 인증을 요구합니다. 그룹에 속한 미삭제 문제 한 개의 최신 revision과 전체 정답을 반환하며, 저장에는 기존 `POST /questions`의 revision 충돌 검사를 그대로 사용합니다. 공개 출제 응답에는 정답을 추가하지 않습니다.

인증·요청 제한과 서로 독립적인 DB 조회를 `D1Database.batch`로 묶습니다. 항목 추가는 UPSERT RETURNING으로 저장 결과를 바로 받습니다. 관리 목록은 각 문제마다 분류를 다시 읽지 않고 한 번만 조회합니다. 채점 저장, 중복 제출 확인, 트리거 처리 후 통계 조회는 하나의 DB 배치로 처리합니다. 기존 인증·제한·중복 채점 방지·개인별 우선 출제는 유지합니다.

DB 왕복 횟수: 분류 추가 5→2, 문제 저장 8→3, 5개 관리 목록 10→2, 출제 8→3, 채점 8→3. 쿼리 개수와 DB 왕복 횟수는 다릅니다. 거래 단위가 묶여 네트워크 대기를 줄입니다. DB 구조와 기존 데이터를 변경하는 마이그레이션은 없습니다.

화면에서는 항목 추가 결과를 목록에 즉시 반영하여 `/catalog` 재호출을 없앴습니다. 관리 목록은 펼칠 때 조회하고, 저장 후 목록 갱신은 입력칸을 잠그지 않습니다. 저장 실패 시 입력과 요청 ID를 보존하고, 실제 저장 성공을 받기 전에는 성공으로 표시하지 않습니다. 버튼과 상태 문구는 요청 직후 대기 상태를 표시합니다.

허용된 Origin의 사전 요청 결과를 최대 86400초 캐시하도록 응답합니다. 실제 데이터 응답의 `no-store` 및 Origin 검사와 쓰기 인증은 유지합니다. 브라우저별 캐시 상한은 다를 수 있습니다. `[placement] mode = "smart"`로 DB 통신에 유리한 실행 위치를 자동 선택하도록 했습니다. 위치 최적화에는 트래픽 관찰 시간이 필요하므로 즉시 효과를 보장하지 않습니다.

실제 API 5회씩 측정한 `/next` 중앙값은 1444ms→864ms였습니다(같은 측정 환경, 채점 없이 측정). `/catalog`는 네트워크 변동으로 628ms→682ms였으므로 개선된 것으로 보고하지 않습니다. 저장·채점의 실제 사용자별 지연은 접속 지역과 네트워크에 따라 다릅니다. 이 수치는 브라우저 전체 사용자 경험이나 모든 요청의 보장 시간이 아닙니다. `Server-Timing`의 `app`에는 서버 처리 시간을 노출하며 비밀값은 포함하지 않습니다.

참고: [D1 batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch), [Workers Placement](https://developers.cloudflare.com/workers/configuration/placement/).
